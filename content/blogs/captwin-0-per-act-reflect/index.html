CapTwin (0) Per-Code-Act

Per-Act

控制理论早期，反馈控制把行动写成对偏差的反复修正。目标 r 与观测输出 y 的差记作 e，再由控制器生成动作。闭环稳定时，偏差被限制在目标轨道附近。

具身智能中的感知—运动循环具有相同结构。感知 P 把环境变成内部状态，运动 A 再把内部状态作用于环境。控制理论描述闭环，生物学描述身体。

$$e_k=r_k-y_k,\qquad E_k\xrightarrow{P}S_k\xrightarrow{A(\,\cdot\,,e_k)}E_{k+1}$$

假设一个生物按固定周期运行，时钟把连续生活切成一系列离散时刻。每次滴答触发一次感知和一次运动，上一轮的结果成为下一轮的输入。

从趋利避害的草履虫到智人，都能先放进这个最小回路。差异进入 P、A 与内部状态 S；回路形式保持不变。在这个抽象层级，Per-Act 可以被视为生命活动的一条共同法则。

控制论是否已经表达了一种智能？对维纳而言，也许是。逻辑、信息与反馈共同构成一个能修正偏差的系统。但这与今天的人工智能相隔很远：当时的核心问题是如何传递信息并稳定系统，今天的核心问题还包括如何从数据中获得感知与行动。

经典控制通常先给定动力学，再设计控制律。滑模控制以及由常微分方程或偏微分方程描述的系统，都可以进入这一框架。

现代具身智能把数据放进闭环本身。数据 D 同时塑造感知映射与行动映射；环境产生的新数据，再进入下一轮训练或适应。

$$D\xrightarrow{\mathrm{train}}(P_\theta,A_\phi),\qquad E_k\xrightarrow{P_\theta}S_k\xrightarrow{A_\phi}E_{k+1}\xrightarrow{\mathrm{observe}}D'$$

于是 Per-Act 多出一层时间尺度：身体在短周期内闭环行动，数据在长周期内改变闭环。这个变化也为 CodeGen 提供了入口。

Per-Code-Act

安排重复工作时，我们会写 SOP。SOP 给出步骤，执行者仍要理解文字、识别现场并处理未写出的情况。代码把更多含混处压进可执行的规则，因此能直接驱动机器，也能驱动带有模型的智能系统。

代码执行后会产生数据。它规定系统接收什么、按什么顺序变化、在哪些边界内运行；输出与日志因此成为可以追溯的轨迹。给定目标条件，同一条轨迹可以判定成功与失败，也可以比较不同时刻和环境中的运行。

这延续了一种罗素式的形式化直觉：用符号系统表达对象、关系与推演规则。代码又向前一步，因为这种描述能够运行，并让运行结果反过来接受描述的检验。

把生物写成闭环，仍有一种机械论的嫌疑。人的脑中没有字面意义上的齿轮；不同生物也不共享一套刻在 DNA 中、能够逐行执行的 SOP。进入生命的细节后，特例不断出现，状态转移呈现为条件概率。

$$x_{t+1}\sim p(\,\cdot\mid x_t,a_t),\qquad M_N=\frac{1}{N}\sum_{i=1}^{N}h(x_i)\xrightarrow[N\to\infty]{}\mathbb{E}_p[h(X)]$$

这里 x 是微观状态，a 是作用，h 是我们选择的观测，M 是大量观测的统计量。若样本近似独立，或过程满足相应的遍历条件，单条轨迹中的例外仍可能在足够大的时间、空间或样本尺度上形成稳定模式。

仿真模型把这些模式写成可运行的代码。少量规则生成大量轨迹，模拟统计量再与现实观察比较。规律是否有效，由两边在指定尺度上能否接近来回答。

至少在统计回归与可重复实践覆盖的尺度上，世界没有退化为无法处理的随机性。理性仍能提出规律，观察仍能推翻规律。代码连接这两步，并推动下一次发现。

因此，我偏爱一个更激进的表述：在感知与行动之间，把代码设为边界。感知把世界压缩成可处理的描述；代码把描述组织成可执行的关系；行动把这些关系重新送回世界。

$$E_t\xrightarrow{\mathrm{Per}}S_t\xrightarrow{\mathrm{Code}}\Pi_t\xrightarrow{\mathrm{Act}}E_{t+1}$$

从分析哲学的角度看，这个表述没有那么激进。有意义的思考需要遵循可说明的推理关系，也需要接受事实检验。数学证明、程序与理性推演因此具有相近结构；其中命题—类型、证明—程序的对应可以严格建立，其余关系保留为方法上的类比。

数学家与程序员都在构造可检查的推演，只是使用的对象与执行介质不同。把代码放进闭环还有更强的野心：系统获得了构造环境的能力。这正是仿真路线中的具身智能所依赖的一步。

我们先用代码生成一族可能世界，再让现实观察筛选它们。若模型族足够丰富，真实世界的可观测行为会落在其中，或被其中一个世界逼近。

$$\theta\sim q(\theta),\qquad W_\theta=\operatorname{Sim}(C,\theta),\qquad \theta^*=\arg\min_\theta d\!\left(O(W_\theta),O(W_{\mathrm{real}})\right)$$

这里 q 给出可能世界的分布，C 是仿真代码，O 只取我们能够观察的现象，d 衡量模拟与现实的距离。找到 θ* 后，我们可以在对应世界中复现实象、改变条件，并检验同一规律能否继续成立。

Embodied AI -> Per-Vibe-Act

具身智能远早于今天的热潮。在线与离线强化学习已经把智能放进感知、行动与奖励的循环；受生物学和认知科学启发的研究，也一直试图让这一框架进入机器人身体。它长期存在，只是没有成为人工智能的中心叙事。

第一波变化发生在大语言模型进入公共视野前后。Code as Policies 在 2022 年 9 月让语言模型生成调用机器人 API 的策略程序；RT-1 在同年 12 月把图像、语言指令与机器人动作放进同一个 Transformer。ChatGPT 随后放大了一个问题：高度自动化的语言智能能否同时组织物理行动？

这条路径受制于 API 的作用域。策略程序可以重组已有原语；当任务需要的感知或动作没有进入接口，语言模型也无法越过边界。早期系统证明了连接可以成立，还没有给出足够完整的世界。

第二波是 Vision-Language-Action。RT-2 在 2023 年把视觉—语言模型的网络知识迁移到机器人控制；随后，更大的机器人数据集与模型沿着语言模型的规模化路径前进。

困难落在行动数据上。文本可以被复制，机器人轨迹需要身体、场地、遥操作与安全约束。Open X-Embodiment 聚合了二十二种机器人、超过一百万段 episode；这个规模来自二十多家机构的共同采集，仍难像网络语料那样廉价扩张。

Per-Vibe-Act 提出第三条路径。这里的 Vibe 指一种低人类介入的编程过程：环境 E 被感知为状态 S，系统再生成代码 C、局部环境 Ê 与行动方案 Π。运行结果回到感知，新增经验首先来自可执行世界，然后由真实世界校正。

$$E_t\xrightarrow{\mathrm{Per}}S_t\xrightarrow{\mathrm{Vibe}}(C_t,\widehat{E}_t,\Pi_t)\xrightarrow{\mathrm{Act}}E_{t+1}\xrightarrow{\mathrm{observe}}S_{t+1}$$

代码在这里同时约束行动空间与反馈条件。I 表示条件互信息，H 表示条件熵；只有当程序和可执行环境为行动提供了额外信息，下一步行动的条件熵才会严格下降。这不要求模型本身确定，只要求闭环排除一部分无效路径。

$$I\!\left(A_{t:t+T};C,\widehat{E}\mid O_{\le t},G\right)>0\ \Longrightarrow\ H\!\left(A_{t:t+T}\mid O_{\le t},G,C,\widehat{E}\right)<H\!\left(A_{t:t+T}\mid O_{\le t},G\right)$$

当这个条件熵足够低，高度不确定的智能系统开始呈现控制系统的性质：偏差可见，动作可执行，失败可以进入下一轮修正。范式的变化来自闭环逐渐可控。

Vibe -> Ralph -> Lisa

Per-Code-Act 最近的现实入口是 vibe coding：人描述意图，coding agent 修改代码，人再观察运行结果。这个名称出现于 2025 年 2 月；本文关心的转折发生在 2025 年末至 2026 年初，自动化开始从一次生成走向持续循环。

环境配置、前端实现和工程胶水曾经消耗大量时间。它们拥有明确的文件边界，也能被构建、测试或浏览器观察。Coding agent 因而可以接手许多烦琐步骤；人的工作逐渐从逐行实现移向目标与反馈的设计。

Ralph loop 把这次往返写成外层循环。同一目标被反复交给新的 agent 上下文；repo、计划文件和 git 历史保存跨轮状态。一次生成的偶然性，被下一轮继续工作的能力吸收。

Lisa loop 再加入可执行的评判条件。Repo R 运行后产生输出 o 与退出码 z；退出码为零时闭环停止，失败时，输出被交给下一轮 agent 修复。评论者在这里首先是一段能够判定结果的环境。

$$R_t\xrightarrow{\mathrm{run}}(o_t,z_t),\qquad z_t=0\Rightarrow\mathrm{stop},\qquad z_t\neq0\Rightarrow o_t\xrightarrow{\mathrm{agent}}R_{t+1}$$

在具身智能框架中，这带来一次边界重排。代码既改变环境，也构造环境的局部模型；测试、编译器和浏览器把变化压成新的感知。Coding agent 因而获得一个可重复进入、可以失败、也能由失败改变下一次行动的世界。

范式的变化发生在闭环层面：自动化不再只缩短一次编码，而开始决定系统如何持续观察、行动与修正。

Agent 带来的变化超出智能平权。更多人能够调用模型，也意味着更多人可能构造决策过程，并把决定转成可执行行动。智能、决策与行动力开始沿同一条链分布。

在更远的未来，如果 Vibe 分散到生活的各个角落，同一方法可能进入繁重的体力劳动。面对训练集与预设 API 都没有定义的场景，系统先构造局部环境和判据，再让机器人行动；结果成为下一轮程序与策略的材料。

$$U\xrightarrow{\mathrm{Per}}S_t\xrightarrow{\mathrm{Vibe}}(\widehat{E}_t,J_t,\pi_t)\xrightarrow{\mathrm{Act}}E_{t+1}\xrightarrow{\mathrm{feedback}}S_{t+1}\xrightarrow{\mathrm{revise}}(\widehat{E}_{t+1},J_{t+1},\pi_{t+1})$$

这里 U 是尚未定义的劳动场景，局部环境、评判条件与策略都可以随反馈更新。世界被程序暂时描述，被行动检验，再被失败改写；机器人由此获得自我循环与演化的起点。
