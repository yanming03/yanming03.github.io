Embodied Harness

把 agent 的推理循环接到机器人世界，同时不把仿真器 API 和控制器细节暴露给模型。

Problem

机器人环境通常提供相机、对象句柄、关节状态和控制器调用。模型若直接操作这些接口，prompt 会绑定某个仿真器，轨迹也会混入大量控制细节。

Embodied Harness 把模型接口压缩为语义操作。模型观察图像、定位对象、读取本体状态并执行抓取；provider 决定这些操作来自固定 fixture、仿真真值，还是真实运行的 RoboTwin。

Design

layerresponsibility
agentreason about task outcomes
semantic toolsinspect / locate / grasp / proprioception
capabilitiesobservation / object pose / robot
providersfixture or RoboTwin bridge

工具参数在两种运行环境中保持一致，因此同一个 agent 组合可以先在无密钥 fixture 中验证，再切换到 RoboTwin。图像字节存入 attachment；session 只记录引用、语义输入和技能结果，历史不会被 base64 图像或控制器轨迹淹没。

RoboTwin path

一个小型 Python sidecar 在 RoboTwin 进程内拥有场景，并通过 JSON-RPC 暴露 RGB、对象位姿、关节状态和语义抓取。TypeScript provider 负责连接检查和结果映射，agent loop 保持不变。

仓库中的 captwin 是这条桥接协议的历史名称，不是另一项必须安装的软件。运行真实 demo 只需要现有 RoboTwin checkout、它的 Python 环境和一个模型 API key。

Use it

当前实现覆盖 RGB 观察、特权对象位姿、关节本体感知和抓取。无密钥 demo 验证完整工具序列与持久化事件；真实组合通过同一组语义工具连接 RoboTwin。
